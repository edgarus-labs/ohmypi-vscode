# oh-my-pi for VS Code

A native VS Code client for the [oh-my-pi (OMP)](https://github.com/can1357/oh-my-pi) coding-agent runtime.

The extension is a frontend only. OMP remains the runtime and the source of truth for providers, credentials, models, sessions, agents and subagents, tools (including LSP, DAP and MCP), approval policy and session persistence. The extension starts `omp --mode rpc-ui` and talks to it over OMP's documented JSONL RPC protocol (`docs/rpc.md` in the OMP repository). It never parses terminal output.

## Requirements

- VS Code 1.106 or newer, locally or in a remote extension host.
- A trusted workspace: in Restricted Mode the extension does not start OMP. Trusting the workspace starts OMP.
- A folder on disk, local or remote. Virtual workspaces (for example GitHub Repositories in the browser) are not supported.
- An installed and configured OMP (`omp`, tested with 18.5.1). Configure providers, logins and models with OMP itself, for example by running `omp` once in a terminal. The extension has no provider settings and stores no credentials.

## Installation

```sh
code --install-extension oh-my-pi.vsix
```

Or open the Extensions view, choose `...` > `Install from VSIX...` and select the file.

To build the VSIX from source:

```sh
npm install
npm run package          # writes dist-vsix/oh-my-pi.vsix
```

## Finding the OMP executable

When `omp.executablePath` is empty, the extension looks for `omp` on `PATH` (on Windows, `omp.exe` and `omp.cmd`), then in `~/.local/bin/omp` and `~/.bun/bin/omp`. A configured path must be absolute or start with `~`; on Windows it must point to a `.exe`, `.com`, `.cmd` or `.bat` file. If it can't find one, the chat shows an "OMP not found" banner with Open Settings and Retry, the Agents and Changes sections show the reason, and a notification offers Open Settings.

## Working directory

OMP runs in the first workspace folder, also in a multi-root workspace. With no folder open it runs in the folder of the active file, or else in your home directory, and starts only when you first use it (a prompt, a command or **Start OMP**).

On Windows, `omp.cmd` (the npm install) cannot run in a folder on a network or WSL share (`\\server\share\…`, `\\wsl.localhost\…`), because it runs through cmd.exe, which does not accept such a folder; OMP then fails to start and says so. Point `omp.executablePath` at `omp.exe` for such workspaces.

## Layout

OMP lives in its own panel in the **Secondary Side Bar** on the right, like Claude Code, GitHub Copilot Chat and Codex, so the Explorer and your editors stay where they are. Open it with the OMP icon on the right, `OMP: Open in Side Bar`, or the `OMP: …` status bar item; toggle the whole right panel with `View > Appearance > Secondary Side Bar` (Ctrl+Alt+B / Cmd+Option+B). The panel has three sections:

- **Chat**: the conversation and the input box. The section title bar has New Session, Session History and Abort (while busy); Rename, Open Session, Restart, Show Log and Settings are in its `...` menu.
- **Agents** (collapsed by default): one row per agent, labelled with the subagent's OMP name (`ReviewAuth  scout · running · read src/auth.ts`), subagents nested under their parent, running agents first. The section title shows how many are running.
- **Changes** (collapsed by default): one row per file changed by OMP, with status, folder and line counts (`M · src/auth · +3 −1`). Click a file for VS Code's native diff in the editor area. Starting a new session clears the list and closes its diff editors.

## Features

- **Chat**: a thin header shows state, session name (click to rename), elapsed time while working, context and cost, and the status texts OMP extensions publish (after `compacting…`, joined with `·`). The oh-my-pi tier router's status is shortened to `router auto`, `router auto · <tier>`, `router off · subagents only`, `router · classifier down` or `router paused · manual model, /tier-auto resumes`; while it is paused, a **Resume auto** button sends `/tier-auto`, and while it chooses the model the composer's model button reads `<model> · tier auto`. The status bar items show the same short tier text. User and assistant messages stream in as they arrive. Thinking is collapsed (`thinking · N lines`). The transcript follows new output only while scrolled to the bottom (otherwise a "jump to latest" button appears).
- **Tool calls**: each call is a header row (status icon, tool name, workspace-relative primary argument or file link, detail on the right) over a dim preview of its input (`IN`, arguments as `name: value` lines; copying them yields indented JSON) and result (`OUT`), always visible. `show more` opens the whole call (up to 2000 lines in a scrolling box of at most 500 px), `collapse` closes it again and `Copy all` copies text past the display limit. A finished `read` shows only its header until opened, failed calls keep their first error line, and calls started in the background show a clock. Shell rows put the call's description in the header, the command and other parameters in `IN`, and drop OMP's `Wall time` / exit-code trailer from the output. Code in tool output, arguments and replies is syntax-colored with calm theme colors (comments italic); `read` listings get an unselectable line-number gutter, search results mark their matches, code fences are stripped and one-line JSON is indented for reading (copying keeps the original). Edits show inline diffs with the changed words marked (20 lines, then `show more`), output that looks like a diff renders as one, and multi-file edits get a link and a `Diff <file>` per file. Results render as Markdown only for reads of Markdown files and MCP or generic tools whose output looks like Markdown.
- **Input box**: the toolbar inside the input box has the **model** (`Claude Haiku 4.5 ▾`, opens the model picker), the **reasoning effort** (`auto · low ▾`, see below), **fast** mode, the **editor context** toggle, and Send. Enter sends and Shift+Enter starts a new line. While the agent is working, Send becomes Steer, Follow-up queues a message for after the turn, and Stop aborts the turn; Alt+Enter queues a follow-up and Esc stops the turn from the keyboard. On a narrow panel these buttons wrap onto their own row. A prompt that cannot be sent (for example while OMP is restarting) stays in the input box with its attachments, and the error is shown. Queued-message chips, a todos strip (`todos 2/5 · current: …`; its `×` hides it, also after a reload, until the todos change) and pending approvals and questions sit above the input box. `OMP: Send Prompt` reveals the panel and focuses the input. With editor context on, the prompt is prefixed with the workspace folder, the active file and cursor position, the selection (up to 8 KB), the other open editors inside the workspace folders, the active file's diagnostics, the workspace's error and warning counts, and the files changed in git (up to 30). The toggle follows `omp.includeEditorContext` until you change it yourself; after that your choice is kept across reloads.
- **Slash commands**: typing `/` at the start of the input lists the commands OMP reports (builtins, skills such as `/skill:…`, extension, custom and file commands), with aliases, argument hints, descriptions and their source; the list follows OMP when its commands change. It filters by name prefix, alias and substring; after `/command ` it lists that command's subcommands (for example `/effort ` or `/mcp `). Up/Down move, Enter or Tab inserts the command without sending, Escape closes, and a click inserts too; with the list closed, Enter sends as usual. OMP runs the command and its output appears in the conversation.
- **Sending and progress**: your message appears in the conversation as soon as you press Enter, dimmed until OMP records it. Commands you send (for example `/rules`) stay visible above their output, in monospace beside a slash icon; when OMP expands a command into a longer prompt, the expansion is under a collapsed section. Commands are sent without the editor context, so OMP runs them as commands. While the agent works, a status row at the end of the conversation shows what it is doing ("Sending…", "Thinking…", "Compacting…", "Stopping…", "Waiting for background work…"), the turn's elapsed time and the output tokens so far; it hides while OMP waits for your answer and respects "reduce motion". After each turn a dim line sums it up, for example `Worked 1m 12s · 12.3k in · 2.1k out · 8k cached · $0.0123` (`Stopped after …` or `Failed after …` when it did not complete), with input, cache read, cache write and output tokens in its tooltip; resumed sessions show it for past turns too. The line under each reply shows its model, with the reply's tokens and cost in the tooltip. Your messages and finished replies have a copy button (on hover or focus), and a thin rule separates an answer from the tool calls before it.
- **Links**: file names in replies (`src/extension.ts`, `extension.ts:12`, `a.ts#L5`, Markdown links to files) and the path in a file-tool row's header open the file in the editor, by click or Enter. A bare file name that is not found relative to OMP's working directory is searched in the workspace: one match opens, several show a picker, none shows `File not found`. Web and mail links (Markdown links and bare `https://` URLs) open in the browser; any other scheme is refused. Replies also render italics, and code blocks have a Copy button.
- **Reasoning effort**: the selector lists `off`, OMP's `auto` (for every reasoning model) and the efforts OMP reports for the current model. With `auto`, OMP chooses the effort for each turn; the selector keeps showing `auto`, as `auto · low` once OMP has resolved the turn, and its tooltip shows the effective level. Picking an explicit level replaces `auto` until you pick `auto` again. The selector shows OMP's own setting on startup and after switching sessions (read from the session journal), so an `auto` default in OMP's configuration appears as `auto`. The setting applies to the current session, as in OMP; the default stays in OMP's configuration.
- **Attachments**: everything attached to the next message is shown as a chip above the input with an `×` to remove it.
  - **Files and folders**: the `+` button in the input toolbar opens a picker over the open editors and workspace files (select several with Space); `Add File to OMP Chat` is also in the editor, editor tab and Explorer context menus (multi-select works). Files are sent as OMP `@path` mentions, so OMP reads them itself with its own size limits and formatting.
  - **Long pasted text** (more than 10 lines or 1000 characters) becomes a `Pasted text N · L lines` chip instead of landing in the input; it is sent as a `<pasted-text>` block and shown collapsed in the conversation. Shorter pastes go into the input as usual.
  - **Images** pasted into the input or dropped onto it become thumbnail chips and are sent to OMP as image content, so vision-capable models see them: up to 10 MB each, 8 per message and 20 MB in total. Dropped files that are not images are rejected with a warning.
- **Prompt lifecycle**: the extension follows OMP's lifecycle. A prompt is accepted, the agent works, the agent yields (`prompt_result`) and the session settles (`session_settled`). An acknowledgement on its own is never treated as completion, and the UI stays "busy" until the session settles.
- **Model picker** (the model button in the input box, or `OMP: Select Model`): lists the models OMP reports through `get_available_models`, grouped by provider (the current provider first) and, within a provider, by family with the newest revision first in natural order (GPT-5 before GPT-10); models with the same name are told apart by id. Each row shows the context window and `$in / $out` price, the detail line the max output, thinking efforts and input modalities, and the current model is marked. Search matches name, id and provider. A row's buttons star the model as a favorite or copy its id; the title bar's Favorites and Recent filters, your favorites and your last 20 picks are remembered across sessions. Nothing is hard-coded. Fast mode (the `fast` toggle or `OMP: Toggle Fast Mode`) shows OMP's error when the current model doesn't support it.
- **Usage**: `OMP: Show Usage` (or the gauge button in the chat header) opens a popup over the transcript with each provider's rate limits from OMP's `/usage`: a bar, the percent used (warning from 80 %, error at 100 %) and the reset time, with Refresh and Close; Esc closes it. Limits are named by quota bucket when `omp usage --json` reports them. The report does not enter the conversation.
- **Sessions**: New Session and Session History (resume any session stored next to the current OMP session) in the Chat title bar; rename, open the raw session file, and abort (which also cancels every running or pending subagent). While the conversation is empty, the chat follows the connection (`Starting OMP…`, `OMP stopped: …`, or a **Start OMP** button while OMP is not running) and, once OMP is ready, lists the most recent sessions with a link to the full history. The last session of each workspace is resumed when the extension starts; if that session file is gone or an OMP extension refuses it, the chat shows a warning.
- **Agents view**: shows the main agent and OMP subagents. Click an agent to open its transcript; the tooltip lists status, model, activity, tool count, tokens, cost and duration. It updates from OMP's `subagent_lifecycle` and `subagent_progress` events, with no polling. Actions: open transcript, inspect, steer, and cancel (cancel kills the subagent through OMP's `cancel_subagent`).
- **Tool rendering**: specialized renderers for read, write, edit and ast_edit (path links and colored diff), grep, glob and ast_grep, bash and eval (live output, exit code), task (subagents), lsp, debug, MCP tools and jobs. Any unknown tool falls back to a generic renderer.
- **Changes view**: lists files changed by OMP tools. Click a file to open VS Code's native diff of the content before the change against the current file, or open the file itself.
- **Approvals and questions**: OMP `confirm`, `select`, `input`, `editor` and `ask` requests appear inline in the conversation and take focus unless you are typing. When the conversation is hidden, a notification with a native quick-pick or input-box fallback also appears. Nothing is ever auto-approved. If an answer cannot be delivered, the question stays open and the error is shown. Answers to `input` requests are never written to the RPC trace. OMP's approval policy (`tools.approvalMode`) is configured in OMP.
- **Process management**: the extension negotiates protocol v2, including reassembly of chunked frames, and handles stdout and stderr separately. If OMP exits unexpectedly, the chat and a notification (with Restart and Show Log) report it together with OMP's last stderr lines, and the extension restarts it with bounded backoff (3 attempts within 60 s) and re-binds the current session. On shutdown it closes stdin, then sends SIGTERM and then SIGKILL to the process group (on Windows, `taskkill /T /F` on the process tree), so stopping OMP from the extension leaves no OMP processes behind. On Windows, processes OMP itself started (shell tools, MCP servers, language servers) can outlive an OMP that exits by itself, because `taskkill` needs the parent alive to find them.
- **Session cost**: the header's cost is the running sum of the main agent's replies. After a compacted session is reloaded OMP returns only the messages after the compaction, so the total restarts from there; subagent cost is not included.
- **Accessibility**: screen readers hear each finished reply, notice and question once; streaming text and the elapsed timer are not read out. Notices expand with Enter or Space.
- **Changes and file links outside the workspace**: change tracking only follows files inside OMP's working directory and the workspace folders. Opening a file link or tool diff that points outside the workspace asks for confirmation first.
- **Agent control of VS Code**: the extension registers `vscode_*` host tools with OMP every time it starts, so agents can operate the editor, not just chat in it. They run in the extension host through the VS Code API, and a failure comes back to the agent as a tool error; OMP's `host_tool_cancel` cancels a call, and calls in flight are cancelled when OMP stops. Every path argument must lie inside OMP's working directory or a workspace folder; other paths are refused. `vscode_execute_command` is not limited this way: it runs any registered command, internal ones included, with any arguments, so through it an agent can open, edit or run things outside the workspace. Results are capped at 40,000 characters. Approval of tool calls is OMP's policy, as for any tool.

| Area               | Tools                                                                                                                                                                                                                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace          | `vscode_workspace` (workspace folders, working directory, active and open editors)                                                                                                                                                                                                                              |
| Documents          | `vscode_documents`, `vscode_open_document`, `vscode_read_document` (editor buffer, so unsaved edits are seen), `vscode_replace_lines` (edits the buffer with undo, stays unsaved), `vscode_save`, `vscode_close_document`, `vscode_selection`                                                                   |
| Problems and tasks | `vscode_diagnostics` (Problems panel), `vscode_tasks` (list tasks, or run one and wait for its exit code and the errors and warnings it left)                                                                                                                                                                   |
| Debugger           | `vscode_debug` (start a launch configuration with or without debugging, stop, pause, continue, step into/over/out, state; continuing and stepping wait until the debuggee stops again), `vscode_breakpoints` (list, add with optional condition, remove), `vscode_debug_inspect` (evaluate, call stack, locals) |
| Anything else      | `vscode_find_commands` and `vscode_execute_command` run any VS Code command (`editor.action.formatDocument`, …) with JSON arguments                                                                                                                                                                             |

## Commands

`OMP: Open in Side Bar`, `OMP: Add File to OMP Chat`, `OMP: New Session`, `OMP: Session History`, `OMP: Rename Session`, `OMP: Select Model`, `OMP: Select Thinking Level`, `OMP: Toggle Fast Mode`, `OMP: Send Prompt`, `OMP: Abort`, `OMP: Restart`, `OMP: Open Session`, `OMP: Open Settings`, `OMP: Show Agents`, `OMP: Show Log`, `OMP: Show Usage`, `OMP: Clear Changes`. The extension adds no keybindings. VS Code also generates `Focus on Chat View`-style commands for each view; `Open in Side Bar` is the one to use.

## Configuration

These settings cover the frontend only:

| Setting                    | Default      | Purpose                                                                                                                                                                                                                                             |
| -------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `omp.executablePath`       | `""`         | Absolute path to `omp` (or starting with `~`); empty means search as described above. Machine scope: set it in your user settings (or the remote machine's settings), never in a workspace's `.vscode/settings.json`, which VS Code ignores for it. |
| `omp.extraArgs`            | `[]`         | Extra CLI arguments for `omp --mode rpc-ui`, for example `["--profile", "work"]` or `["--approval-mode", "always-ask"]`. Machine scope, like `omp.executablePath`: a repository cannot change how OMP is started.                                   |
| `omp.startup`              | `resumeLast` | `resumeLast`, `newSession` or `manual`. With `manual`, OMP starts on the first prompt or command and resumes the last session (New Session starts a fresh one).                                                                                     |
| `omp.autoRestart`          | `true`       | Restart OMP after an unexpected exit.                                                                                                                                                                                                               |
| `omp.logLevel`             | `info`       | Verbosity of the `oh-my-pi` output channel.                                                                                                                                                                                                         |
| `omp.traceRpc`             | `false`      | Log abbreviated RPC frames; takes effect immediately. Answers to `input` requests are redacted.                                                                                                                                                     |
| `omp.includeEditorContext` | `true`       | Default state of the composer's editor-context toggle.                                                                                                                                                                                              |

Providers, models, MCP servers, agents, approval policy and session storage are configured in OMP (`~/.omp/agent/config.yml`, `omp` commands), not here.

## Development

```sh
npm install
npm run typecheck
npm run test:unit         # mocha in Node (protocol, process, session, agents, UI helpers, webview with linkedom)
npm run test:integration  # VS Code extension host against test/fixtures/fake-omp.mjs
npm run test:integration:min  # the same suite against the oldest supported VS Code (engines minimum)
npm run test:real         # VS Code extension host against a real OMP (model requests only with OMP_IT_MODEL set)
```

Development needs Node 22.23.4, 24.22.1 or 26.12.1 or newer (earlier releases are affected by CVE-2026-111497; `engines.node` enforces this). `npm run test:unit` caps the test process heap at 1.5 GB (the suite peaks at about 140 MB), so a runaway test fails instead of exhausting a build agent's memory. On a machine without a display, wrap the integration runs in `xvfb-run -a`. The integration suite runs on a pinned VS Code version; pass `--vscode-version=<version|min>` or set `OMP_IT_VSCODE_VERSION` to pick another, or set `OMP_IT_VSCODE=<path to code binary>` to reuse an already downloaded VS Code. Set `OMP_IT_EXECUTABLE=<path to omp>` for `test:real`, and `OMP_IT_MODEL=<provider>/<model id>` to run its real turns (model switch, auto effort, real edit with native diff); without it only the handshake and model-discovery test runs and the other three are reported as pending. Unit tests can be built into a separate directory with `node esbuild.mjs --tests --outdir=out/<name>`.
